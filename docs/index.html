01 · Contexto

Sobre o desafio

O desafio acadêmico transforma uma revisão manual de legado em um fluxo repetível: detectar a stack, entender a arquitetura efetiva, encontrar anti-patterns, produzir uma auditoria rastreável, solicitar aprovação humana, refatorar e validar o comportamento.

A mesma skill foi aplicada aos três projetos, sem presumir Python, Flask ou uma estrutura de diretórios específica.

06 · Playbook

Exemplos de transformação

O playbook traduz cada problema em uma mudança verificável de responsabilidade ou segurança.

SQL concatenado→SQL parametrizado
Password inseguro→Hashing apropriado
God Class→Controller + Service + Repository
Business Logic em Route→Service
Conexão global→Lifecycle / Unit of Work
N+1→JOIN / eager loading / batch
Hardcoded config→Environment / config
Deprecated API→API moderna
Error handling espalhado→Handler centralizado

08 · Síntese

Principais aprendizados

Skill agnóstica

Identifica responsabilidades e padrões, não nomes de arquivos.

Contexto importa

Severidade depende do uso real da aplicação.

Deprecated precisa de evidência

Código antigo não significa automaticamente API deprecated.

Refatoração incremental

Projetos organizados não precisam ser reconstruídos do zero.

Human in the Loop

A PHASE 2 sempre pausa antes de qualquer alteração.

Validação real

Boot, testes e endpoints verificam as refatorações.
